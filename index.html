what is this

// skip if you want to

enclave messenger is the first piece of project enclave — started because i live in Manipur, India, where internet shutdowns are real. when they happen, whatsapp, upi, telegram — all of it dies. they all depend on central servers that suddenly can’t be reached.

that’s a stupid design. so i’m trying to build something different — a messenger that finds peers directly over whatever medium is available. internet, LAN, bluetooth, LoRa radio. whatever works.

it’s not finished. it’s a hobby project. but i genuinely care about this one.

how it works (roughly)

// the architecture in a tree

transport layer
  ├── internet      → raw DHT (kademlia-based, no central tracker)
  ├── local network → nmap-style peer discovery
  ├── sms           → via local or cloud sms api
  ├── bluetooth     → arduino / esp32 / device api
  └── lora          → arduino / esp32 (long range, low bandwidth)

identity layer
  ├── ed25519 keypair  → who you are (signing)
  └── x25519 prekeys  → how sessions start (key exchange)

crypto layer
  └── noise protocol + double ratchet → e2e encryption per conversation

ui
  ├── flutter → desktop + android (main targets)
  └── python bridge → web ui

no accounts. no servers. user id is derived from your public key. nobody can take it from you.

crypto

// how it stays private

ed25519

your identity keypair. used for signing. who you are on the network.

x25519 prekeys

used to establish sessions. lets two devices agree on a shared secret without ever sending it.

noise + double ratchet

end-to-end encryption per conversation. forward secrecy. inspired by signal’s protocol.
